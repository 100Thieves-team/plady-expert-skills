# 알고리즘 문제 풀이 도메인 — 도메인·비즈니스 탐색 기획서 (v1)

> **목적**: "알고리즘 문제 풀이" 도메인 안에서 *어떤 제품/비즈니스*를 할지, *차별점*을 어디서 가져올지를 넓게 탐색하고 근거를 남겨, 다음 회의에서 팀·멘토가 방향을 결정할 수 있게 한다.
> **결론 성격**: 하나로 못 박지 않는다. 7개 후보를 균형 있게 펼치되 후보별 차별점·리스크·2주 MVP·검증 실험은 날카롭게 제시한다. **최종 선택은 팀 회의 몫.**
> **작성 방식**: 이 레포의 알고리즘 도메인 전문가 스킬(`aps-*` 13종)과 기획 에이전트(assumption-mapping·product-manager 등)를 다중 에이전트로 협업시켜 리서치·검증·평가한 결과를 통합했다. 경쟁 지형은 웹 리서치로 사실 대조했고, 각 차별점 주장은 별도의 회의적 검증 단계를 통과시켰다.
> **작성일**: 2026-07-04 · AlgoMate PoC 스펙시트는 후보 C1의 한 구현 예시로만 인용(유일 정답 아님).

## 1. 배경 · 문제의식

- **팀 목표**: ① 2026-09 하반기 공채 취업, ② 실사용자가 꾸준히 쓸 서비스 출시, ③ 프로젝트 전 과정 AI 적극 도입.
- **우선순위**: (1) 재미·지속가능성 → (2) 문제 해결 → (3) 수익. (수익은 3순위 — 본 문서는 실사용자 획득 중심, 수익 모델은 경량 언급만)
- **피봇 맥락**: PDF 학습 서비스에서 알고리즘 문제 풀이 도메인으로 전환(확정). PDF는 (a) 도메인이 포괄적이라 페르소나를 못 잡았고, (b) UnivAI가 이미 장악해 차별화가 어려웠으며, (c) 문제가 AI에 지나치게 의존적이라 **재미가 반감**됐다. 이 세 교훈은 이번 탐색의 평가 잣대로 그대로 살아 있다.
- **수렴 방향**: 갈래 B(제품·실사용자 우선) + 갈래 A(기술·취업)도 포기 안 함. **"기술 중심보다 우리가 하는 방식에 맞춰 만들고, 기술을 그 뒤에 붙인다."**
- **비협상 조건**: (준서) 실사용자 없으면 재미없다 / 기술 깊이 없으면 아쉽다. (팀) 2주 안에 껍데기라도 배포한다. **3명(백2·프1)의 기술이 한 프로젝트에서 맞물려야 한다**(프론트도 재밌어야 — Gen UI/디자인시스템 관심). 취업 스토리(설계·운영·모니터링)를 남긴다.
- **성공 기준**: 주기적으로 방문하는 실사용자 두 자리수, 2주마다 배포 흐름, 자소서 메인 키워드가 될 소재.

## 3. 알고리즘 문제 풀이 도메인 지도

### 3.1 대전제 — "문제→코드→AC"가 아니라 **라이프사이클**이다

```
문제 발견/선정 → 읽기/해석 → 모델링·제약분석 → 아이디어·알고리즘 선택
→ 정당성·복잡도 추론 → 구현·로컬테스트 → 제출·판정 해석 → 디버깅 → 복습·정착·전이
```

모든 기능은 이 라이프사이클의 특정 구간을 개선/보호/측정/조율할 때만 의미가 있다. 코어 활동(라이프사이클)을 9개 지원 서브도메인(학습·추천·판정·설명·AI조력·평가·스터디소셜·지표·저작권)이 감싼다. **후보를 가르는 것은 뼈대가 아니라 "어느 지원 서브도메인을 코어로 끌어올리느냐"다.**

### 3.2 제약 3개가 우리를 "Look-back 사분면"으로 민다 (핵심 통찰)

| 제약 | 함의 |
|---|---|
| **저작권** (지문·입출력·예제 표시/저장 금지) | 라이프사이클 앞구간(읽기·모델링)은 *남의 땅*. 지문을 만져야 하는 개입은 대부분 저작권 지뢰 |
| **2주 배포** | 외부 저지 실행·샌드박스 채점이 필요한 개입은 2주 밖. 정적 콘텐츠 + 가벼운 로깅 + 메타데이터 계산만 2주 안 |
| **dogfooding** | 우리 팀이 곧 코테 스터디 → *스터디 특유의 막힘*에서 콜드스타트가 가장 싸다 |

→ **세 제약이 무게중심을 한 곳으로 민다: 뒷단 "Look-back"(제출 해석 → 디버깅 → 복습 → 재도전).** 이 구역은 **(a) 저작권 안전, (b) 2주 내 구현 가능, (c) solved.ac·백준·프로그래머스가 거의 비워둔 차별화 지대**라는 삼중 정합이 성립하는 유일한 곳이다. 대부분의 학습 고통은 지문-중심 중간부에 있지만, **우리가 싸게·안전하게·차별적으로 이길 수 있는 곳은 "AC 이후"다.** (유일하게 앞구간을 겨냥하는 후보가 C7)

### 3.3 정체성을 가르는 결정: **Attempt vs Submission**

제출(Submission)만 추적하면 읽기·힌트·포기·복기 등 여정의 대부분을 놓쳐 **submission-only 도구(=solved.ac 아류)**로 전락한다. 최소 Attempt 객체 — `문제ID + 시작시각 + (선택)stuck-type/phase + 종료상태{AC/포기/미제출}` — 를 v1부터 못박으면, 코드 없이도 "진행 중"이 성립하고 이 로그가 이후 모든 후보(추천·코치·운영자 콘솔)의 **데이터 해자**가 된다. **어느 후보를 고르든 이 결정을 먼저 하라.**

### 3.4 2주에 넣을 수 있는 "작은 개입" 후보 (라이프사이클 진단)

| 개입 | 저작권 | 저지의존 | 크기 | 먹여주는 후보 |
|---|:--:|:--:|:--:|---|
| **A. Stuck-type 1탭 + phase 태깅** | 안전 | 없음 | ◎ 2~3일 | C2·C6·추천 (데이터 해자 씨앗) |
| **B. Verdict-to-Cause 가이드** (WA/TLE/RE 원인 체크리스트) | 안전 | 없음 | ◎ 2일 | C3 (AI 디버깅의 비-AI 씨앗) |
| **D. AC 후 복기 로그 1줄** | 안전 | 없음 | ◎ 2~3일 | C2·C4 |
| C. 제약 sanity 체커 (N·복잡도→TLE 예측) | 안전 | 없음 | ◎ | C7(시각화)·C2 |
| F. 제출 캡처 + 히트맵/독촉 | 코드=사용자 | 익스텐션 | △ 4~6일 | C1·C6 |
| G. 같은 문제 코드 비교 diff | 코드=사용자 | F 선행 | △ | C1·C4 |
| H. 침묵의 고투 보드 | 안전 | A 선행 | △ | C1·C6 |

> **가장 싼 단독 승부**: A+B+D (셋 다 ◎·저작권 안전·저지 비의존). "우리는 AC 이후를 다룬다"는 solved.ac 대비 즉각 차별점이 되고, 3명 모두 붙을 일이 있으며, 첫날부터 dogfooding 된다. 스터디 색을 넣으려면 여기에 F를 얹는다.

## 4. 경쟁 지형 (사실 대조)

### 4.1 결정적 사건 — 백준 그룹 공백 (최대 기회, 단 리스크 동반)

- **[검증됨]** 백준(BOJ)은 16년 1인 운영자 체제로 운영되다 **2026-04-28 서비스 종료** → **2026-06-11 데이원컴퍼니가 인수, '제로베이스' 브랜드로 부활**. 종료 시 문제·제출기록·대회를 제외한 데이터(사용자 정보·게시판·**그룹**)가 전부 삭제됨. 인수 직후 개인정보 유출 사고(이름·이메일·전화·암호화 비번)도 발생.
- **[미검증]** 부활 백준이 **그룹 기능을 예전처럼 복구·유지하는지, 과거 기록을 복구하는지는 확인 불가**. 부활 발표는 "이용 방식 큰 변화 없이 유지" 수준의 원론.

→ 한국 스터디의 진도·랭킹 **표준 축(백준 그룹)이 붕괴**했다. 저지 위에 얹는 '운영 대시보드'가 진입할 진공이 열렸다. **단, 교훈 두 개**: (1) 부활 백준이 그룹을 다시 강화하면 공백이 메워질 수 있다 → **특정 저지에 종속되지 말고 멀티 저지(백준·프로그래머스·LeetCode) 가로지르는 운영 허브로 설계**하는 것이 안전판. (2) 백준 사태는 평가축 7(저작권·외부의존 리스크)을 실제 사건으로 입증했다 → **"우리는 지문/데이터를 소유·의존하지 않는다"가 강한 방어 서사이자 취업 스토리.**

### 4.3 화이트스페이스 요약

1. **운영/가시성 레이어**가 구조적으로 비어 있음 — 멤버×문제 히트맵·제출률·미제출 자동 독촉·같은 문제 코드 diff·또래 리뷰. 지금은 Google Sheets 수기 + 카톡 수동 독촉. (C1·C6·C4)
2. **AI는 조연 자리가 명확** — 코테 도메인엔 AI 학습 보조가 비어 있으나, 정답을 대신 풀어주면 재미·무결성 붕괴. 빈자리는 *오답 진단·약점 추천·풀이 후 리뷰 보조*. (C2·C3)
3. **저작권 회피 설계 자체가 차별점** — 메타+사용자 코드만 다루는 자세가 문제 제공자와 충돌 없이 '운영·협업·리뷰'를 얹는 유일한 안전지대.
4. **캡처는 재구현 금지** — BaekjoonHub/LeetHub가 이미 성숙. 캡처 자체는 차별점이 아니며, 진짜 가치는 그 위에 얹는 레이어.

## 5. 제품 방향 후보 (C1~C7)

> **읽는 법**: 각 후보의 "차별점"은 두 층으로 본다 — **주장**(naive framing)과 **검증 후 남는 wedge**. 우리 리서치의 가장 중요한 정직한 발견: **7개 후보 모두, 넓은 차별점 주장은 회의적 검증에서 부분 반박(partly)됐다.** 시장은 생각보다 붐빈다. 살아남는 차별점은 "없던 기능"이 아니라 **"성숙 부품 통합 + 그 위 가시화/복기 레이어"**로 정밀화한 좁은 wedge다. 온보딩 때 즉시 반박당하지 않으려면 이 정밀화가 필수다.

### C1 — 스터디 운영 플랫폼 (AlgoMate 계열) · 총점 27
**"몇 개 풀었나가 아니라, 이 그룹이 이번 주 어디서 막혔고 무엇을 배웠나를 보여주는 스터디 운영 허브."**

- **페르소나**: 코테 스터디 **리더/운영자**(매주 문제 선정·수기 진도 취합·카톡 독촉을 반복). 2차: 멤버(자기 진도·복기), 멘토(async 가시성). 백준 그룹 삭제로 페인 급등. **우리 팀 자신 = 이 페르소나 → 즉시 dogfooding.**
- **코어 루프**: 리더가 문제집(메타만) 배정 → 멤버가 풀이+제출 캡처+**stuck-type/phase 1탭 Attempt** → 히트맵·자동 독촉으로 가시화(마감 전 답/태그 봉인) → 마감 후 코드 diff + **침묵의 고투 보드**가 모임 안건화 → AC 후 복기 로그 → 다음 주 반복.
- **차별점**: (주장) 아무도 안 채운 그룹 단위 운영/가시성 레이어. **(검증=partly)** 넓은 '진공'은 반박됨 — CodeMate·99클럽·(부활)BOJ그룹·GitHub PR·잔디가 인접 점유, 캡처는 BaekjoonHub가 성숙. **생존 wedge**: *Attempt 단위 '침묵의 고투' 가시화 + AC 후 복기 + 개인→그룹 전환* + **멀티 저지 운영 허브**(저지 종속 회피).

- **AI 위치**: 조연 — 코호트 리스크 요약·독촉 초안·리뷰 포인트 제안(전부 사람이 최종 판단). C1이 쌓는 Attempt 로그가 훗날 C2형 코치로 AI를 키울 연료.
- **2주 MVP(조건부 가능)**: 익스텐션 자동캡처·멀티저지 실시간 동기화를 빼고 **붙여넣기+히트맵+자동독촉+코드 diff+Attempt/복기**로 좁힘. 관건은 3인 동시 통합 범위 폭발 → 제출 캡처를 '수동 붙여넣기'로 못박아 방어.
- **최상위 위험 가정**: *외부 스터디가 '그룹 단위(전원 80%+)'로 옮겨탄다.* 가치가 전원 참여에 걸려 있어 개인 단위 채택이면 붕괴. **검증**: 배포 후 소마 외 스터디 1~2개를 컨시어지 온보딩 → 주1 로스터 대비 Attempt 커버리지 ≥80% + 실제 모임에서 히트맵/고투 보드가 화면공유·안건화되는지.

### C2 — 개인 약점기반 코치 · 총점 23

### C5 — 모의 코테·대회 시뮬레이터 · 총점 22
**"혼자 무제한 연습으론 안 길러지는 '실전 시험 감각'을 스터디가 함께 반복 훈련하고, 시험 직후 복기(upsolve)로 전환한다."**

### C3 — AI 오답 디버깅 튜터 · 총점 20 (AI 주연)
**"막힌 순간, 답을 주지 않고 '왜 틀렸는지'를 코드 기반으로 진단한다."**

- **페르소나**: 코드는 썼고 '거의' 맞는데 WA/TLE/RE를 반복하는 **중급 solver**(BOJ Silver~Gold). **반전**: 가장 절실한 건 표면상 초보지만, 초보의 막힘은 읽기·모델링(저작권 잠금 구역)이라 진단할 코드가 없다 → **C3가 안전하게 도울 수 있는 유일한 층은 중급**(구현·엣지·복잡도 오개념).
- **코어 루프**: WA → 코드+verdict 붙여넣기 → **자기 가설 먼저 강제 입력**(integrity+metacognition) → verdict별 원인 후보를 hint ladder로(기본 L3 상한) → 수정→재제출 → AC 후 active-recall 1줄 + N일 후 무도움 재풀이.
- **차별점**: (주장) 저지(verdict만)와 ChatGPT(바로 고쳐줌) 사이 빈 공간. **(검증=partly)** 반박됨 — CS50.ai 덕 디버거·LeetCopilot 단계힌트·OSS 확장이 코테 도메인까지 점유. **진짜 경쟁자는 무료 ChatGPT.** **생존 wedge**: *'일부러 덜 도와주기' + assistance level 로깅 + 모드별 가드레일* — 학습 보존 축에서 ChatGPT를 이긴다는 것. 팔리면 해자, 안 팔리면 무료 대체재에 즉사.
- **3인 맞물림 △**: BE1=동기화+secret redact 파이프라인, BE2=hint ladder를 server-side로 강제하는 AI 가드레일 엔진(OWASP LLM01 방어·assistance 로깅). **FE가 진단 인터랙션(단계 공개·active recall·diff 하이라이트)을 소유 못 하면 리포트 뷰어로 전락 → 비협상 조건 위반 위험.**
- **AI 위치**: **주연(구조적으로 불가피) · 최고위험 · integrity-first 조건부.** aps-ai-assistance-integrity 스킬 전체가 바로 이 제품을 위한 것. 규율(레벨 상한·독립성 로깅)을 서버측으로 강제 못 하면 피봇 실패를 재현.
- **2주 MVP(조건부 가능)**: 1주차 = AI 없는 껍데기(정적 Verdict-to-Cause+자기가설+복기), 2주차 = LLM 진단 얇게(server-side cap·불확실성 표시·secret redact). **배포 O, 2주 후 유지 △**(막힐 때만 옴).
- **최상위 위험 가정**: *중급 solver가 무료 ChatGPT가 있는데도 '덜 도와주는' 학습 보존형을 선택·반복 사용한다.* **검증**: 막힌 사용자에게 within-subject로 경로A(단계 힌트) vs 경로B(바로 고쳐주기)를 붙여, 자기효능감·무도움 재풀이·**다음 막힘 때 자발 재선택**을 측정.

### C7 — AI 알고리즘 풀이 시각화 (Gen UI) · 총점 18 (AI 주연)
**"임의의 알고리즘/사용자 코드를 정확한 동적 시각화로 — 내 코드가 실제로 어떻게 움직이는지."** *(회의록 갈래 A 대표안. 팀은 '기술 first라 안 할 것 같다'고 예측 — 그럼에도 원래 고려안이라 공정 평가)*

- **페르소나**: 재귀 트리·DP 테이블 채워지는 순서·BFS 프런티어 같은 **'시간에 따른 상태 변화'를 머릿속에서 못 굴리는** 시각형 입문~중급 학습자. **유일하게 라이프사이클 앞구간(모델링·아이디어)을 정면으로 겨냥**(나머지 6개는 전부 '제출 이후').
- **코어 루프**: 막힌 코드 붙여넣기 → AI Gen UI가 시각화 생성 → 타임라인 스크럽으로 상태 변화 관찰 → "예상과 다르네"(오개념 교정) → 수정 후 재시각화. **⚠ '막힐 때만' 도는 저빈도·episodic**.
- **차별점**: (주장) 임의 코드를 AI가 동적 시각화(VisuAlgo/Python Tutor식 고정셋 초월). **(검증=partly)** 반박됨 — AlgoCademy 'AI viz'·LeetCopilot recursion tree·dStruct·Codedive가 이미 점유, Python Tutor/VisuAlgo가 절반을 무료 커버. **생존 wedge**: *맥락·소유·언어(내 제출코드×스터디 리뷰×한국어)*로 좁혀 사실상 **C1/C4의 리뷰 심화 기능으로 흡수** — 독립 후보로선 약함.
- **3인 맞물림 ✕(불균형)**: **프론트 재미·포트폴리오는 7개 중 최강**이나, **백엔드 2명 맞물림이 얇아 비협상 조건('3명 맞물림')을 껍데기 단계에서 이미 아슬아슬하게 위반**. 트레이서/샌드박스를 넣어야 백엔드가 사는데 그 순간 팀의 no-execution 결정과 충돌+2주 초과. Pyodide로 회피하면 백엔드 몫이 'AI API 래퍼'로 증발.
- **AI 위치**: **주연(구조적) · 딜레마.** '주연이면 위험(오개념 주입), 조연으로 낮추면 차별점 소멸(VisuAlgo 수준)'. 시각화를 AI가 다 만들면 사용자의 모델링(사고)을 대체 → **PDF 피봇의 'AI 의존→재미 반감' 이유가 정확히 재발.**
- **2주 MVP(조건부 가능, 좁힌 껍데기)**: Python 1개+아키타입 3~4개+Pyodide 트레이스+타임라인. **주의**: '임의 코드 신뢰 시각화'는 2주 밖이고, 껍데기는 좁은 VisuAlgo 아류로 수렴하며 이미 3인 맞물림 불만족.
- **최상위 위험 가정**: *AI가 '임의' 코드를 학습에 쓸 만큼 신뢰 가능하게(=은근히 틀리지 않게) 시각화한다.* 무너지면 오개념을 권위 있게 주입. **검증**: 팀이 안 고른 실제 코드 30~50개로 블라인드 정확도 감사 → **silent-wrong rate < 5%** & correctness 게이트 recall.

### 급소 대응 — GitHub 코드리뷰 대비 포지셔닝 (C1·C4·C6)

**문제 제기**: 스터디는 이미 GitHub PR로 코드를 관리하고, BaekjoonHub가 AC 코드를 GitHub에 자동 푸시한다. GitHub의 인라인 리뷰·스레드·알림은 강력·무료·친숙하다. **코드리뷰를 정면으로 재구현하면 진다**(diffVerify가 C4 헤드라인을 바로 이 이유로 반박).

**그러나 GitHub PR 리뷰는 "이 변경을 main에 머지할까?"를 위한 도구다.** 알고리즘 스터디 맥락에선 좌표가 어긋난다 — GitHub가 *구조적으로* 못 하는 것이 우리 wedge다:

| GitHub PR 리뷰 | 알고리즘 스터디가 진짜 원하는 것 |
|---|---|
| **브랜치 diff** (내 변경 vs base) | **문제 단위 N-인 비교** (BOJ 1753에 대한 3명의 *독립* 풀이를 나란히) — GitHub엔 이 뷰가 없어 3개 파일을 눈으로 대조 |
| 푸시하면 **전원 즉시 열람** | **reveal-gating** (내가 AC/포기 전엔 남 풀이 잠금) — 스터디 최대 페인 '먼저 푼 사람이 답 흘림'을 GitHub는 못 막음 |
| 파일/커밋/폴더로 조직 | **문제·verdict·성능·진도에 바인딩** (난이도·태그·제출률·히트맵·미제출 독촉) — GitHub는 AC/WA/티어를 모름 |
| 코드 diff만 | **성능·복잡도 diff** (132ms 우선순위큐 O(E log V) vs 1204ms 선형 O(V²)) |
| 머지 지향 리뷰(LGTM/nit) | **학습 지향 리뷰**(왜 이 접근/복잡도/다음엔) — 실제로 스터디 PR은 대부분 LGTM만 찍고 진짜 리뷰가 안 됨 |

즉 GitHub의 리뷰 **엔진(스레드·알림·친숙함)은 강하지만 그 엔진이 앉은 좌표(브랜치 머지)가 우리 문제(문제 단위 학습 비교)와 다르다.**

**세 갈래 대안**
- **A. 정면 대결 (비추천)** — GitHub보다 나은 리뷰 UI를 재구현. 무료·친숙한 강자와 기능 싸움 → 진다.
- **B. 재프레이밍** — "코드리뷰 도구" 간판을 내리고 **"문제 단위, 스포일러-세이프 또래 비교"**로 축 이동. GitHub는 per-PR, 우리는 per-problem — *다른 원시개념(primitive)*이라 기능 비교 자체가 성립 안 함.
- **C. 끌어안기 = 통합 (추천)** — BaekjoonHub가 이미 GitHub로 푸시하니, **GitHub를 코드 저장소로 읽어오고 그 위에 '문제 단위 비교 + reveal-gating + 진도/verdict 바인딩' 레이어만 얹는다.** "GitHub = 코드 창고, 우리 = 그 위 학습 레이어." 사용자가 강한 무료 도구를 안 버려도 되고, diff·알림을 재발명 안 해도 되며 빌드도 준다(§5 C1의 "캡처는 BaekjoonHub, 우리는 그 위" wedge를 리뷰까지 확장).

**후보 선택 함의**: 이 급소는 **"리뷰를 코어로 세우는 C4"보다 "운영/가시성을 코어로 세우는 C1"을 강화**한다. 리뷰는 *간판이 아니라 GitHub 연동 부가 기능*으로 두고, 차별화는 GitHub가 못 하는 **딱 2개 — ① 문제 단위 N-인 비교, ② reveal-gating** — 에만 건다. 나머지(침묵의 고투·독촉·복기·멀티저지 진도)는 GitHub와 겹치지도 않는 C1 고유 영역이다. *확인 숙제*: `CodeMate`·`99클럽` 등 인접 서비스가 이미 'GitHub 연동 스터디 리뷰'를 하는지 사실 확인 필요(현재 미검증).

### 후보 선택과 무관하게 걸리는 공통 규율

1. **차별점 문장을 diffVerify가 남긴 좁은 wedge로 정밀화**한다 (넓은 '진공' 주장 금지 — 온보딩 때 반박당함).

## 7. AI의 위치 판정 (사용자 요청: "기획서가 결정")

### 이 도메인의 정답 기본값은 **조연**이다 (7후보 중 5개)

C1·C2·C4·C5·C6은 코어가 비-AI(운영/가시화·심리측정 진단·또래 리뷰·타임박스 채점)이고 AI는 부가 레이어로만 얹힌다. **구조적으로 AI가 주연일 수밖에 없는 건 C3·C7 딱 2개**이며, 공교롭게 이 둘이 **피봇 실패를 재현할 위험이 가장 큰 후보**다. 우연이 아니다 — 풀이 도메인에서 AI를 '코어 가치'로 올리는 순간, 팀이 도망쳐 나온 '풀이를 AI에 맡기는' 조건이 재생성된다.

### 팀의 단일 규칙

> **"AI를 크리티컬 풀이 경로(solving path)에 올리지 말고, 리뷰·운영·설명·빌드 과정에 둔다."**

피봇 실패의 본질은 AI를 *풀이 경로 위*에 둔 것이다(AI가 문제를 대신 풀어줌 → 몰입·재미 소멸). 안전한 AI는 풀이 경로 *밖*에 있다 — 풀이 후 복기, 오답 진단, 운영/독촉 보조, 그리고 **개발 과정**. 이 규칙 하나로 목표③과 피봇 교훈이 동시에 만족된다.

### 목표③은 '조연'으로도 완전히 충족된다

과제 정의대로 조연 = *제품 코어는 비-AI, AI는 부가 기능 + **개발 과정 적극 활용***이다. 즉 목표③의 'AI 적극 도입'은 (a) 빌드/운영 과정의 AI 활용, (b) 부가 기능(요약·진단·독촉 초안), (c) C1/C6이 쌓는 Attempt·이벤트 로그가 곧 미래 AI(C2형 코치)의 연료가 되는 경로로 충분히 달성된다. **지금 조연은 AI 야망의 포기가 아니라, 의존 함정 없이 더 깊은 AI로 갈 권리를 먼저 버는 것.**

또한 조연 후보에도 진짜 **AI 무결성 엔지니어링 취업 서사**가 있다: server-side assistance cap, prompt-injection(OWASP LLM01) 방어, assistance-level 로깅, secret redact·국외이전 consent, correctness 게이트. AI를 제품 코어로 안 올려도 백엔드 재미와 goal③을 동시에 채운다.

### 후보별 권고

| 후보 | AI 위치 | 핵심 |
|---|---|---|
| C1·C6 | **조연** | 코어(동기화·집계·시각화)가 전부 비-AI. AI는 리스크 요약·독촉 초안·리뷰 제안 |
| C2 | **조연** | 코어 지능은 IRT/BKT+자체 데이터(방어선). LLM은 진단 자연어화·복기 프롬프트만 |
| C4 | **조연(엄격한 상한)** | 차이 요약·리뷰 포인트 초안까지만. AI가 리뷰 대신 쓰면 커뮤니티 가치 소멸 |
| C5 | **조연 + mode-gating** | 시험 중 명시적 OFF(무결성), 복기에서만 ON. "AI를 끌 줄 아는 제품"이 차별점 |
| **C3** | **주연(불가피) · integrity-first 조건부** | 서버측 힌트 상한·'의도적 덜 도와주기'를 정책으로 강제 못 하면 무료 ChatGPT에 즉사 |
| **C7** | **주연(불가피) · 딜레마** | 결정론적 correctness 게이트 + predict-then-check 필수. 못 걸면 피봇 실패 재현 |

> **⚠ 만들지 말 것**: 'AI-generated 코드 탐지' 기능(신뢰 불가·오고발). 탐지가 아니라 자체 assistance 로그(provenance)에 의존한다.

## 8. 공통 제약 (저작권 · 외부 저지 의존) — 채택 무관

> 법률 자문 아님. 이슈를 드러내고 안전한 방향을 제시. 최종 확정은 각 플랫폼 한국어 ToS·정보통신망법·PIPA와 counsel로 검증 필요.

1. **지문 저작권**: 지문·입출력·예제는 **표시·저장·캐시 금지**가 유일한 안전선. 저장 가능한 건 메타데이터(번호·제목·난이도·태그·링크)뿐. **paraphrase·번역·요약도 derivative-work 리스크** — "요약해서 담자"는 우회가 아니다. (특히 C5 문제 제공, C7 시각화 소스, C3·C4 해설)
2. **크롤링/스크래핑**: '해도 되나'는 CFAA·ToS·저작권 3개 별개 질문. 공개 ≠ 복제 허가. **서버측 크롤링보다 사용자 주도 import**(본인 제출 캡처=private-use)가 안전. 익스텐션도 대상 ToS의 자동화 조항 확인 + 캡처를 메타+본인코드로 한정(지문 텍스트 캡처 금지).
3. **제출 코드·개인정보(PIPA)**: 사용자 코드+제출 이력=개인정보. consent·목적고지·retention·**삭제/내보내기(법적 의무)** 필요. **"메타+코드만 저장"은 저작권 답이지 개인정보 답이 아니다.** 그룹 내 타인 코드 노출(코드 diff)은 참여자 consent 전제. 외부 LLM 전송=국외이전(no-train tier·DPA·별도 consent).
4. **외부 저지 의존·종료**: 핵심 가치는 자체 보유 메타+사용자코드만으로 동작하게 설계, 외부 종료 시 degrade만 되게. 폴백=링크아웃+붙여넣기. **백준 사태가 이 리스크를 실증.** 자체채점(testcase-ac) 폴백은 hidden test·지문 저작권 재소환하므로 도입 전 재검토.
5. **미성년자**: under-14(PIPA 법정대리인)/교실 배포(FERPA·학교 consent) 여부 결정. 안 받으면 age-gate. (C1 스터디, **C6 부트캠프 특히**)

### AlgoMate의 저작권 자세 평가

**저작권 축에서는 가장 정합적**(metadata-only + link-out + user-code = 교과서적 안전 전략). 다만 한계: ① **PIPA를 통째로 비워둠**(consent/삭제/내보내기 없음 — 가장 큰 공백), ② **구글 리다이렉트는 방패가 아님**(공식 원문 링크아웃으로 충분·더 안전. 검색 상위가 무단 미러면 오히려 침해 사이트로 유도), ③ 익스텐션 자동캡처의 ToS 검증 부재. **개선 우선순위**: consent/retention 추가 → 구글 리다이렉트를 공식 링크아웃으로 단순화 → 익스텐션 캡처 범위·ToS 문서화.

## 부록 C. 산출 방식

이 기획서는 이 레포의 알고리즘 도메인 전문가 스킬 13종(`aps-domain-architect` 외)과 기획 에이전트를 다중 에이전트 워크플로우로 협업시켜 만들었다: (1) 도메인 지형·경쟁·저작권 프레이밍 → (2) 후보 C1~C7을 담당 서브도메인 전문가 관점으로 심화 → (3) 각 차별점 주장을 회의적 검증자가 경쟁사 사실과 대조(그 결과가 §5의 'partly 반박'과 wedge) → (4) 7축 평가 매트릭스 + AI 위치 판정. 원자료(후보별 상세·North Star·가드레일·검증 실험 전문)는 요청 시 추가로 정리해 제공 가능.
